# THCHS-Derived Tone Slice Dataset Design

## Goal

Build a reproducible Mandarin tone experiment dataset from the public THCHS-30 corpus by deriving syllable or short-word audio slices with tone labels from transcript pinyin tone digits, then use that dataset for acoustic, pretrained-representation, and fusion model experiments.

## Current state

The server project at `/NAS/yesh/mandarin-tone-feedback` already contains:

- validated THCHS-30 archive: `data/downloads/data_thchs30.tgz`;
- checksum file: `data/downloads/data_thchs30.tgz.sha256`;
- extracted corpus: `data/raw/thchs30/data_thchs30`;
- source record: `data/PUBLIC_AUDIO_SOURCES.md`;
- server activation script: `activate.sh`, using the user's existing `/NAS/yesh/NLP/.conda/selfrag` environment.

The existing `data/metadata.csv` generated by utterance-level dominant-tone labeling is not suitable for final experiments because it is heavily imbalanced and has no useful tone-3 coverage. It should be treated as an exploratory artifact, not as the final training dataset.

## Data source

Primary source:

- THCHS-30 / OpenSLR SLR18
- Source page: https://www.openslr.org/18/
- License stated on source page: Apache License v2.0; free for academic users
- Local archive: `data/downloads/data_thchs30.tgz`
- Local extraction root: `data/raw/thchs30/data_thchs30`

Each THCHS `.wav.trn` under `data/` contains:

1. Chinese word-segmented text;
2. pinyin tokens with tone digits;
3. phone-level tokens with tone digits.

Split folders (`train`, `dev`, `test`) contain real wav files and short `.trn` reference files that point back to `../data/*.wav.trn`.

## Revised data strategy

Create a derived dataset of audio slices instead of using whole utterances as tone examples.

### Target unit

The primary unit is a short pinyin token or short word-like slice, not a whole sentence.

Each output row should have:

```csv
audio_path,text,pinyin,tone,speaker_id,split,source_utterance,start_sec,end_sec,source_dataset,label_method
```

Fields:

- `audio_path`: sliced wav path relative to `data/`;
- `text`: Chinese token when available, otherwise pinyin token;
- `pinyin`: pinyin token with tone digit, such as `ma3`;
- `tone`: integer in `{1,2,3,4}`;
- `speaker_id`: derived from utterance stem prefix, such as `A11`;
- `split`: `train`, `val`, or `test`;
- `source_utterance`: original THCHS wav path;
- `start_sec`, `end_sec`: approximate slice boundaries;
- `source_dataset`: `THCHS-30 / OpenSLR SLR18`;
- `label_method`: description such as `pinyin_tone_digit_with_energy_slicing`.

### Slice derivation

The first implementation should use a deterministic approximate alignment strategy:

1. Read the pinyin tone sequence from each `.wav.trn` file.
2. Remove neutral-tone tokens (`5`) and non-tonal tokens from the candidate list.
3. Load the wav and estimate duration.
4. Allocate approximate token intervals across the utterance duration in transcript order.
5. Refine each interval using short-time energy around its estimated region when possible.
6. Export each accepted slice as a small wav under `data/processed/thchs30_slices/<split>/`.
7. Validate each slice by duration and voiced F0 availability.

This is not a substitute for forced alignment. It is a reproducible approximation suitable for a course project if limitations are clearly stated.

### Quality filters

Accept a slice only if:

- tone is one of `1`, `2`, `3`, `4`;
- duration is between 0.18 s and 1.20 s;
- audio is not silent by RMS threshold;
- F0 extractor finds voiced frames with voiced ratio at least 0.2;
- per-tone per-split quota has not been exceeded;
- source speaker split is respected.

Recommended first pilot quota:

- train: up to 400 slices per tone;
- val: up to 80 slices per tone;
- test: up to 80 slices per tone.

If THCHS distribution cannot fill these quotas for a tone, the script must report the actual counts and continue without fabricating samples.

## Experiment pipeline

### Acoustic baseline

Input: derived slice metadata.

Features:

- normalized F0 start;
- normalized F0 middle;
- normalized F0 end;
- F0 range;
- F0 slope;
- duration;
- voiced ratio.

Output:

- metrics JSON;
- confusion matrix CSV;
- acoustic feature arrays;
- one F0 example plot per tone if feasible.

### Pretrained representation baseline

Input: derived slices.

Process:

- load short wav slices at 16 kHz;
- extract frozen hidden states with wav2vec2 or HuBERT from the existing NAS environment;
- mean-pool utterance states;
- train a lightweight classifier.

Output:

- representation feature arrays;
- metrics JSON;
- confusion matrix CSV.

### Fusion model

Input:

- acoustic features;
- pretrained representation features;
- labels and split arrays.

Process:

- concatenate aligned feature rows;
- train a lightweight classifier;
- evaluate on the same test split.

Output:

- fusion metrics JSON;
- fusion confusion matrix;
- model comparison table.

## Paper and presentation framing

Use cautious wording:

- Correct: “We derive a syllable/short-word tone experiment subset from THCHS-30 transcripts using pinyin tone digits and deterministic energy-based slicing.”
- Correct: “The labels are transcript-derived rather than manually segmented syllable labels.”
- Incorrect: “THCHS-30 provides isolated tone labels.”
- Incorrect: “The dataset is a manually annotated single-syllable tone corpus.”

Limitations to state:

- boundaries are approximate;
- coarticulation and sentence prosody remain in slices;
- neutral tone and unstressed syllables are excluded;
- results evaluate a reproducible derived subset, not a full learner pronunciation corpus.

## Error handling and stopping rules

- If a `.trn` file cannot be resolved, skip the utterance and log it.
- If audio cannot be loaded, skip the utterance and log it.
- If a tone class cannot reach the quota, report the actual count; do not synthesize or duplicate samples.
- If metadata validation fails, do not train.
- If F0 extraction fails for too many samples, revise slice filters before training.
- If pretrained feature extraction fails due to model/cache issues, run acoustic baseline first and report representation training as pending.

## Verification strategy

Before training:

- Unit-test pinyin tone extraction;
- unit-test `.trn` reference resolution;
- unit-test interval generation;
- unit-test metadata row shape;
- run a small pilot slice generation with low quotas;
- validate metadata with `experiments/dataset.py`.

After slice generation:

- report counts by tone and split;
- inspect several slices per tone manually or by duration/F0 summaries;
- save provenance to `data/processed/thchs30_slices/README.md`.

After training:

- verify metrics files exist;
- verify test split metrics are used;
- generate a model comparison table only from metrics files;
- update paper result slots only from real outputs.
